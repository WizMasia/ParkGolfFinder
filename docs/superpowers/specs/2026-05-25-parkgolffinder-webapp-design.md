# ParkGolfFinder 웹앱 설계 초안

## 목표
- 대한민국 내 파크골프장을 **목록/검색 중심 웹앱**으로 제공한다.
- 사용자가 시설을 빠르게 찾고, 상세에서 **예약정보와 요금 정보**를 확인할 수 있게 한다.
- 지도는 핵심 탐색 수단이 아니라 **보조 확인 수단**으로 둔다.
- 운영용 내부 스냅샷은 유지하되, **사용자에게는 DB 기반 화면만 제공**한다.

## 제품 범위
### 포함
- 시설 목록
- 검색 / 필터
- 현재 위치 기반 거리 검색
- 광역권역 탭 탐색
- 시설 상세
- 예약 정보 표시
- 요금 / 경로우대 표시
- 지도 보조 표시
- 운영용 내부 스냅샷 저장

### 제외
- 예약 대행
- 사용자 계정
- 사용자별 북마크/즐겨찾기
- 결제
- 운영중이 아닌 시설 노출

## 전체 UX 방향
- 첫 화면은 **시설 목록**이다.
- 기본 노출은 **현재 위치 기준 10km 이내 시설**이다.
- 위치 권한이 없으면 **서울시청 기본 좌표**를 기준점으로 삼되, 지도와 목록은 계속 보여준다.
- 위치가 없을 때는 **광역권역 탭**으로 탐색한다.
- 카드에는 처음엔 **시설명 / 거리 / 이용료 요약**만 보여준다.
- 상세 화면은 **예약정보와 요금**을 먼저 보여준다.

## 위치와 거리 규칙
### 위치 권한이 있을 때
- 브라우저 위치를 받아 현재 위치를 사용한다.
- 기본 거리 범위는 **10km**다.
- 거리 범위는 슬라이더로 조절한다.
- 검색 결과는 **거리 순, 동률이면 이름 순**으로 정렬한다.
- 10km 이내 시설이 하나 이상이면 그 범위의 시설만 보여준다.
- 10km 이내 시설이 없으면 **가까운 순 10개**를 보강해서 보여준다.

### 위치 권한이 없을 때
- 현재 위치 기반 검색은 사용할 수 없다.
- 기본 좌표는 **서울시청**으로 둔다.
- 목록은 광역권역 탭 기반으로 탐색한다.
- 이때도 시설 목록은 계속 보여준다.

## 권역 탐색 규칙
- 권역은 **광역권역 탭**으로 제공한다.
- 권역 예시:
  - 수도권
  - 강원권
  - 충청권
  - 호남권
  - 영남권
  - 제주권
- 권역 안에서는 **거리 순, 동률이면 이름 순**으로 정렬한다.

## 목록 화면
### 기본 카드 정보
- 시설명
- 거리
- 이용료 요약

### 목록에서 숨기는 것
- 예약 방식 상세
- 운영 상태 태그
- 지도 미리보기
- 긴 설명 텍스트

### 목록 필터
- 시설명 검색
- 지역 / 권역
- 시설종류
- 유/무료
- 경로우대 ON/OFF
- 거리 슬라이더

## 상세 화면
상세 화면 상단은 아래 순서로 둔다.

1. 요약 상단
2. 예약정보
3. 요금 / 경로우대
4. 지도
5. 운영기관 / 연락처

### 상단 요약에 포함할 것
- 시설명
- 주소
- 거리
- 이용료 요약
- 예약방식 요약

## 운영 상태 규칙
- 운영상태는 사용자에게 태그로 노출하지 않는다.
- **운영중인 시설만 결과에 포함**한다.
- 운영예정 / 임시중단 / 미운영 / 확인필요 상태는 목록에 표시하지 않는다.
- 운영상태는 내부 검수 및 노출 제어용이다.

## 요금 / 경로우대 규칙
- 요금 정보는 원본 그대로 저장한다.
- 경로우대는 **유저가 ON/OFF만 선택**한다.
- 앱은 우대 대상 여부를 판정하지 않는다.
- 대신 저장된 데이터 중 **경로우대 적용 시 표시값**이 있으면 그 값을 보여준다.
- 없으면 기본 요금 정보를 보여준다.

### 표시 예
- 경로우대 OFF: `5,000원`
- 경로우대 ON: `무료`
- 경로우대 ON: `50% 할인`

## 예약정보 규칙
예약은 단일 여부보다 **예약방식의 조합**으로 다룬다.

### 예약방식 예시
- 전화
- 인터넷(선착순)
- 인터넷(추첨)
- 방문
- 예약불가

### 설계 원칙
- 한 시설에 예약방식이 여러 개일 수 있다.
- 예약방식은 별도 하위 테이블로 분리한다.
- 각 방식은 태그 + 상세 펼침으로 보여준다.
- `예약불가`도 하나의 방식으로 저장할 수 있다.

## 데이터 모델 개요
### Facility
시설의 기본 본체.

### FacilityPricing
시설의 기본 요금과 경로우대 표시값.

### ReservationInfo
시설의 예약 정보 묶음.

### ReservationMethod
예약 방식 개별 항목.

### FacilitySnapshot
운영용 내부 스냅샷.

## Facility 필드 초안
| 필드 | 설명 |
|---|---|
| `id` | 기본 키 |
| `name` | 시설명 |
| `address` | 원본 주소 |
| `province` | 시/도 파생값 |
| `district` | 시/군/구 파생값 |
| `regionKey` | 검색/필터용 내부 권역 키 |
| `facilityType` | `outdoor`, `indoor` |
| `status` | `active`, `hidden` |
| `ownership` | `public`, `private` |
| `operatorName` | 운영기관명 |
| `phone` | 연락처 |
| `lat` | 위도 |
| `lng` | 경도 |
| `sourceName` | 원천 데이터 이름 |
| `sourceUrl` | 원천 링크 |
| `lastCheckedAt` | 마지막 검수 시점 |
| `createdAt` | 생성 시점 |
| `updatedAt` | 수정 시점 |

### 주소 파생 원칙
- `address`가 원본이다.
- `province`, `district`는 주소에서 파싱한 파생값이다.
- 지역 필터와 표시 편의를 위해 따로 저장한다.
- 주소가 바뀌면 파생값도 재계산한다.

## 관계
- `Facility` 1 : 1 `FacilityPricing`
- `Facility` 1 : 1 `ReservationInfo`
- `ReservationInfo` 1 : N `ReservationMethod`
- `Facility` 1 : N `FacilitySnapshot`

## 내부 스냅샷 역할
- 재구성
- 복구
- 검수 추적
- 매칭 규칙 변경 시 재생성 근거

이 스냅샷은 내부 저장용이며 사용자 화면에 노출하지 않는다.

## 비고
- 거리 자체는 DB에 저장하지 않는다.
- 현재 위치는 런타임 입력값이다.
- 거리는 요청 시점에 계산한다.
- 운영중인 시설만 노출한다.
